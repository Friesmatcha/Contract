# 企业合同智能审核与风险预警系统需求说明

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 基于大模型的企业合同智能审核与风险预警系统 |
| 文档版本 | v1.0 |
| 文档性质 | 面向实际开发的产品与技术需求 |
| 需求来源 | 2026 省赛赛题开发手册 A24 |
| 目标用户 | 企业法务、风控人员、业务审核人员、系统管理员 |

本文档描述第一阶段可运行产品（MVP）及其扩展边界。系统采用千问商用 API，支持多角色权限和组织级数据隔离。标准条款采用“内置基线模板 + 管理端可维护”的方案：系统安装后即可演示，业务人员又可以在不修改代码的情况下维护企业规则。

## 2. 产品目标

### 2.1 业务目标

将合同审核从人工逐页阅读，转变为“机器初审 + 人工复核 + 风险预警”的协同流程，缩短审核时间，并让每条风险都有原文依据、风险等级、处理建议和明确的处置状态。

### 2.2 第一阶段目标

1. 支持 `.docx`、可复制文本的 PDF、扫描 PDF 和常见图片上传。
2. 支持采购合同、销售合同、保密协议、服务外包合同、劳动合同 5 类合同。
3. 完成合同类型识别、关键要素抽取、风险识别分级、标准条款比对、缺失条款检测、风险预警和报告导出闭环。
4. 所有审核结论均能定位到原文页码、段落或字符区间，并记录使用的模型、规则和模板版本。
5. 支持管理员维护用户、角色、风险规则和标准条款；审核员可以复核、修改和标注结果。

### 2.3 非目标

第一阶段不承诺自动签署合同、替代律师给出最终法律意见、直接修改原始合同、对印章真伪作出鉴定，也不把知识图谱和复杂多轮改约作为系统运行的前置条件。这些能力作为后续迭代项保留接口。

## 3. 用户角色与权限

系统以组织（企业）为数据隔离边界。用户只能访问所属组织的数据，超级管理员负责平台级配置。

| 角色 | 主要职责 | 核心权限 |
| --- | --- | --- |
| 平台管理员 | 维护平台和模型配置 | 管理组织、模型密钥、系统参数、全局审计日志 |
| 组织管理员 | 维护本企业配置 | 管理本组织用户角色、模板、风险规则、数据和报表 |
| 审核员/法务 | 执行合同审核并处置预警 | 上传合同、查看任务、复核风险、接收/处理预警、修改建议、导出报告、提交反馈 |
| 业务查看者 | 查看业务范围内结果 | 查看已授权合同、报告和预警状态，不得修改规则、审核结论和预警状态 |

权限要求：

- 用户、角色、模板、风险规则和合同数据均按组织隔离。
- 审核员的修改必须保留修改前后内容、操作者和时间。
- 组织管理员修改模板或风险规则后生成新版本，已完成的审核仍引用原版本。
- 删除操作默认采用软删除；已被审核任务引用的版本不可物理删除。

## 4. 典型业务流程

```text
创建审核任务
  -> 上传合同
  -> 文件校验与病毒/类型检查
  -> 文本解析或 OCR
  -> 合同分段与页码定位
  -> 合同类型识别
  -> 关键要素抽取
  -> 风险识别与分级
  -> 标准条款比对、缺失检测
  -> 生成审核报告
  -> 根据风险等级和预警规则生成预警
  -> 站内通知相关角色并进入预警待处置
  -> 审核员复核、修改、标注风险和预警
  -> 关闭/升级预警
  -> 导出报告并归档
```

任务状态至少包括：`待处理`、`解析中`、`审核中`、`待复核`、`已完成`、`失败`、`已归档`。失败任务必须显示可读错误原因，并支持在原文件不变时重试。

预警状态至少包括：`待确认`、`处理中`、`已忽略`、`已解决`、`已关闭`。预警不能因为审核任务完成而自动消失，必须保留责任人、处置记录和关闭依据。

## 5. 功能需求

### 5.1 认证、组织与权限（FR-A）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-A01 | 用户登录、退出和密码重置 | 未登录用户不能访问业务接口；密码不会明文存储 |
| FR-A02 | 组织级用户管理 | 组织管理员可邀请、停用和修改本组织用户角色 |
| FR-A03 | 接口权限校验 | 后端每个写接口都校验角色和组织归属，不能只依赖前端隐藏按钮 |
| FR-A04 | 审计日志 | 记录登录、上传、审核、预警处置、规则/模板变更、导出和删除等关键操作 |

### 5.2 合同上传与文档解析（FR-D）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-D01 | 支持 `.docx`、`.pdf`、`.png`、`.jpg`、`.jpeg` | 文件扩展名和 MIME 类型双重校验；超限文件有明确提示 |
| FR-D02 | 提取文本并保留结构 | 保存页码、段落、表格、标题和原始顺序；无法识别的页面标记为 OCR 页面 |
| FR-D03 | 扫描件 OCR | OCR 失败或低置信度页面可单独提示，不得静默生成空文本 |
| FR-D04 | 文档预览 | 结果页可查看原文或页图，并跳转到风险所在页/段落 |
| FR-D05 | 解析幂等与重试 | 相同文件在同一任务内不会重复计费；失败可重试并保留失败原因 |

解析结果必须保存原文件引用、文本版本、页码映射、解析器版本和 OCR 状态。文件大小、页数和单任务并发上限应由组织配置。

### 5.3 合同类型识别与要素抽取（FR-E）

系统首期支持以下合同类型：采购合同、销售合同、保密协议、服务外包合同、劳动合同；无法确定时返回“其他/待确认”，不得强行归类。

至少抽取以下字段：

| 字段 | 说明 |
| --- | --- |
| 合同双方 | 甲方、乙方及其他关键主体，包含原文证据 |
| 签署日期 | 统一为可排序日期，同时保留原始文本 |
| 合同金额 | 金额、币种、含税/不含税信息 |
| 履行期限 | 起止日期或期限描述 |
| 争议解决 | 仲裁机构、管辖法院或其他约定 |
| 付款条件 | 付款节点、比例和逾期责任 |
| 自动续期 | 是否续期、期限和退出方式 |

要求：

- 抽取结果必须使用结构化 JSON Schema 校验，缺失字段返回 `null` 和“未发现/待确认”状态。
- 每个字段保留原文片段、页码/段落位置、置信度和模型请求版本。
- 审核员可修改字段，修改值与原始模型值同时保留。

### 5.4 风险识别与分级（FR-R）

首期预置不少于以下 10 类风险，并允许组织管理员配置：

1. 无限责任或责任范围不封顶
2. 违约金明显过高或计算方式不合理
3. 单方解除/变更权不对等
4. 付款条件不清晰或付款周期过长
5. 验收标准缺失或由单方任意决定
6. 保密义务过于宽泛、期限不合理或缺少例外
7. 知识产权归属不清或单方无偿转让
8. 个人信息、数据跨境或数据合规责任缺失
9. 争议解决地、管辖法院或仲裁机构对本方不利
10. 自动续期、排他或最低采购量等隐性义务
11. 不可抗力、迟延履行或免责条款缺失/失衡

每条风险结果必须包含：风险类型、等级（高/中/低）、风险标题、风险说明、原文片段、位置、判断依据、建议文本、置信度、来源（规则/模型/人工）和处理状态（待复核/已确认/误报/已处理）。

规则与模型采用组合策略：规则负责关键词、数值阈值和必备条款等确定性判断；千问负责复杂语义判断、跨句理解和建议生成。模型提示词、规则版本和输入文本摘要必须可追踪。

### 5.5 风险预警与处置（FR-W）

预警是风险识别结果的运营化输出，不等同于报告中的静态风险列表。系统在审核过程中或审核完成后，根据预警规则把需要关注的风险推送给指定人员，并持续跟踪处置结果。

#### 5.5.1 预警触发

- 高风险发现默认生成预警；中风险是否预警由组织管理员配置。
- 关键条款缺失、标准条款严重偏离、字段抽取置信度过低或模型无法判断时，可配置为“需人工复核”预警。
- 同一审核任务、同一风险类型和同一原文位置在未关闭前不得重复生成相同预警；规则版本变化或人工重新确认时允许生成新事件。
- 预警必须记录触发条件、关联风险/条款、合同、审核任务、触发时间、优先级和目标组织。

#### 5.5.2 预警中心

提供组织级预警列表和合同详情内的预警视图，支持按状态、等级、合同类型、责任人、触发时间和风险类型筛选，并显示未处理数量和高风险数量。点击预警必须能回到风险原文位置。

#### 5.5.3 通知与分派

- 首期必须支持站内通知和待办计数；高风险通知组织管理员和审核员。
- 预警可以由管理员分派给指定审核员，并设置截止时间和备注。
- 邮件、企业微信等外部通知通过通知适配层预留，默认不阻塞首期上线。
- 通知发送失败不影响预警创建，系统记录失败原因并支持重试。

#### 5.5.4 处置闭环

审核员可以确认、误报、忽略、转派、补充说明和标记已解决。关闭预警时必须填写处置结论或引用修改后的合同/审核记录；组织管理员可以重新打开已关闭预警。所有状态变化保留操作人和时间。

#### 5.5.5 履约时间预警（第二阶段）

在要素抽取结果中识别合同到期日、自动续期日、付款节点和履约期限，并由用户选择是否创建提前提醒。该能力属于合同履约监控，不影响首期审核预警闭环。

### 5.6 标准条款比对与缺失检测（FR-C）

#### 5.6.1 模板结构

标准条款模板属于组织配置，至少包含：合同类型、业务场景、模板版本、条款编号、条款名称、标准文本、允许偏差说明、风险等级、适用条件、建议文本、启用状态、生效时间和维护人。

#### 5.6.2 内置基线

系统初始化时提供 5 类合同的演示模板，每类至少覆盖付款、履行/交付、验收、违约责任、保密、知识产权、争议解决、终止/解除等常见条款。基线模板用于开箱即用和测试，不代表任何具体企业的法律意见。

#### 5.6.3 可维护能力

- 组织管理员可以新增、编辑、复制、停用模板和条款。
- 发布修改时必须生成新版本，并要求填写变更说明。
- 支持按合同类型和业务场景选择默认模板。
- 审核任务创建时锁定模板版本；模板后续变化不影响历史报告。
- 第一阶段支持表单维护；Word/Excel 批量导入作为后续扩展，不作为首版依赖。

#### 5.6.4 比对结果

系统应区分“匹配”“存在偏差”“缺失”“无法判断”四种状态，并展示合同原文、标准条款、差异说明、风险等级和补全建议。无法判断时必须交给人工复核，不能当作缺失或通过。

### 5.7 审核结果与报告（FR-RP）

结果页至少包含：

- 合同基本信息和分类结果；
- 风险数量统计及高/中/低风险分布；
- 按风险等级和条款位置筛选；
- 原文定位和上下文查看；
- 要素抽取结果及人工修订入口；
- 标准条款偏差和缺失条款；
- 当前合同预警及其处置状态；
- 审核结论、待处理项和人工反馈。

报告至少支持 HTML 在线预览和 PDF 导出，并包含报告编号、合同文件信息、审核时间、模板/规则/模型版本、基本信息、风险列表、原文依据、建议、缺失条款、人工复核记录和免责声明。报告生成失败时保留审核数据并支持重新生成。

### 5.8 反馈与标注（FR-F）

审核员可以对分类、字段、风险和比对结果执行“正确、错误、修改、忽略”标注，并填写可选说明。系统保存原始结果和人工结果，按组织、合同类型、规则版本和模型版本统计反馈，供后续评估和提示词/规则优化使用。第一阶段不自动用未审核反馈更新生产模型。

### 5.9 配置与运营（FR-O）

- 管理千问 API 配置、模型名称、超时、重试次数和调用预算；密钥只能在服务端读取，前端不得返回。
- 配置文件大小、单用户并发、保留周期和报告水印。
- 查看任务耗时、解析失败率、模型调用失败率、人工修改率和风险误报反馈。
- 查看预警数量、未处理时长、关闭率、误报率和按风险类型的趋势。
- 模型不可用时，系统应保留已完成阶段，并显示“模型服务不可用”，不得生成伪造审核结论。

## 6. 数据实体

核心实体包括：

- `Organization`：组织和数据隔离信息。
- `User`、`Role`、`Permission`：用户、角色和权限关联。
- `Contract`：合同元数据、原文件、所属组织和当前状态。
- `DocumentPage`、`DocumentBlock`：页面、段落、表格、坐标和文本定位。
- `ReviewTask`：一次审核任务及状态、耗时和错误信息。
- `ExtractedField`：字段值、证据、置信度和人工修订。
- `RiskRule`、`RiskFinding`：风险规则版本和具体风险发现。
- `Warning`、`WarningEvent`、`Notification`：预警、预警状态事件和通知投递记录。
- `ClauseTemplate`、`ClauseTemplateVersion`：标准条款及版本。
- `ClauseComparison`：标准条款与合同条款的比对结果。
- `Report`：报告文件、生成参数和版本。
- `Feedback`、`AuditLog`：人工反馈和操作审计。

所有业务实体至少带有组织标识、创建人、创建时间、更新时间和软删除/归档字段（适用时）。

## 7. 外部接口与技术约束

### 7.1 千问 API

通过独立模型适配层调用千问，业务模块不得直接拼接供应商 SDK。适配层至少提供分类、结构化抽取、风险分析和建议生成四类能力，并统一处理：

- JSON Schema 输出和响应校验；
- 超时、限流、重试和幂等请求标识；
- token 用量、耗时、模型版本和错误码记录；
- 敏感数据脱敏开关和日志截断；
- 供应商切换所需的统一接口。

API 密钥只能通过服务端环境变量或密钥配置注入，禁止提交到仓库、前端代码或普通日志。合同内容发送至外部模型前应在系统中明确告知用户并记录调用范围。

### 7.2 推荐技术栈

后端采用 Python + FastAPI，前端采用 Vue 或 React，数据库采用 PostgreSQL（开发环境可使用 Mysql），异步任务可采用 Redis + Celery/RQ，文件存储通过本地目录或对象存储抽象。部署提供 Docker Compose 配置和 CPU 低配置运行说明。技术栈可以调整，但必须保留模型适配、文件存储和任务队列的替换边界。

### 7.3 API 边界

首期接口按资源划分为：认证与用户、组织、合同与文件、审核任务、审核结果、风险规则、标准条款、预警、通知、报告、反馈、审计日志。长耗时审核采用异步任务，创建接口立即返回任务编号，前端通过轮询或 WebSocket 获取任务和预警状态。

## 8. 非功能需求

### 8.1 准确性与可解释性

- 合同分类准确率目标不低于 85%。
- 五项必备字段抽取 F1 目标不低于 80%。
- 预置风险集 precision 和 recall 目标均不低于 75%。
- 每条模型结论都必须关联证据；无证据的结论不得进入“已确认风险”。
- 预警必须可追溯到具体风险或条款，不能只显示无上下文的“合同有风险”。

### 8.2 性能

在单个用户、单个审核任务和正常千问响应条件下，10 页以内文本合同从提交到审核结果和预警生成可在 3 分钟内完成；任务状态和新预警在 5 秒内可被前端感知。性能阈值可按模型套餐和部署资源调整，并在部署说明中记录实测值。

### 8.3 安全与隐私

- 全部业务接口使用鉴权和组织权限校验；重要操作写入审计日志。
- 上传文件使用随机存储名，下载时再次校验访问权限。
- API 密钥、密码和合同正文不得出现在日志中。
- 支持合同和报告按组织配置保留期限；归档或删除操作可追溯。
- 对外部模型调用、数据留存和免责声明在用户界面明确展示。

### 8.4 可用性与可维护性

- 页面在桌面端浏览器可用，并对上传、解析中、空结果、失败、无权限和无数据状态提供明确反馈。
- 后端日志包含请求 ID 和任务 ID；异常不能泄露堆栈或密钥。
- 配置、规则、模板和提示词版本化；核心流程有自动化测试和可重复的评测脚本。

## 9. 评测与验收

评测集由脱敏或公开合同组成，并为合同类型、关键字段和风险条款提供人工标注。评测集与提示词调优数据隔离，避免数据泄漏。

验收至少包括：

1. 五类合同样例均能完成从上传到报告导出的闭环。
2. `.docx`、文本 PDF、扫描 PDF 和图片各至少有一个成功样例；解析失败样例能正确提示并重试。
3. 分类、字段抽取、风险识别达到第 8.1 节指标，输出可导出评测记录。
4. 高风险结果可定位原文，缺失条款和偏差条款可追溯到模板版本。
5. 高风险样例会自动生成预警，目标审核员能在预警中心看到待处理项，并能跳转到风险原文。
6. 预警经过确认、转派、误报、解决和关闭后，状态、责任人、处置说明和时间线均可追溯。
7. 同一风险在未关闭前重复运行审核不会重复生成相同预警，规则版本变化时可生成新的预警事件。
8. 四类角色的越权访问和跨组织访问测试全部失败（即被正确拒绝）。
9. 组织管理员修改模板后，新旧审核任务分别引用对应版本。
10. 千问超时、限流、返回非法 JSON、OCR 失败、通知发送失败和报告生成失败均有可恢复处理。
11. 审核员的人工修改和反馈可以在报告、预警时间线和审计日志中追溯。

## 10. 分阶段交付计划

### 阶段一：可运行闭环

完成登录、基础角色、合同上传、文本解析、千问分类与字段抽取、风险识别、预警规则、预警中心、站内通知、结果页和 HTML 报告。使用内置模板和 5 类合同样例打通“审核完成即产生预警、预警可处置”的闭环。

### 阶段二：企业可配置

完成组织管理、标准条款和风险规则的版本化维护、PDF 导出、人工复核、反馈标注、预警分派、通知重试、审计日志和失败重试。

### 阶段三：质量与运营

完成评测集和指标脚本、任务与预警监控、成本统计、数据保留策略、批量审核和部署文档，补齐权限、安全和性能测试。

### 后续扩展

合同到期/续期/付款节点提醒、多轮对话式修改建议、知识图谱跨条款分析、印章/签名区域定位、Word/Excel 模板批量导入、模型微调或本地模型替换。

## 11. 当前已确定的产品决策

- 模型：千问商用 API；通过适配层封装，保留后续替换空间。
- 权限：平台管理员、组织管理员、审核员/法务、业务查看者四类角色。
- 标准条款：系统提供内置基线，组织管理员可维护版本，历史结果不可被新版本覆盖。
- 预警：审核产生的高风险默认形成预警，站内通知和预警处置属于首期能力；到期/续期/付款节点提醒属于第二阶段。
- 目标：面向实际项目开发，先完成可运行 MVP，再按阶段增加企业配置和运营能力。
